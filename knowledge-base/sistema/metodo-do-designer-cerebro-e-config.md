## O método (regra)
Existe **UM designer** (um cérebro), não um por cliente. O cérebro é fixo: **estuda a faculdade → escreve a copy
→ compõe (HTML+SVG) → renderiza → passa no guardrail**. O que muda de cliente pra cliente é a **CONFIG** — e
**cada config É um cliente**. Os 4 botões da config:

| Botão | O que é | Ex. psi.automatic | Ex. Guaru Estúdio |
|---|---|---|---|
| **Estrutura** | o esqueleto do carrossel | `vitrine-bracket` (dor→prova→pitch) | `conteudo-direto` (hook→CTA) |
| **DNA** | identidade visual (`brand-dna.json`) | preto + gradiente | lime + preto + branco |
| **Guardrails** | linhas vermelhas de marca/ética | CFP + nunca-"IA" | nunca-"IA" + PAS |
| **Nicho** | camada de faculdade a consultar | psicologia | generalista (Base Mãe) |

Trocar o cliente = trocar os 4 botões. Mesmo cérebro, entrega diferente. É isso que permite o "exército":
cliente novo = **só preencher a config**, zero código novo.

## Acúmulo POR cliente (o que faz o designer virar sênior)
Cada cliente tem memória própria: **o designer acumula o aprendizado DAQUELE cliente** em
`Projetos/<cliente>/learning-log.md` (feedback de design por peça) e `learned-lessons.md` (negócio). É lendo essa
memória antes de criar que ele para de errar o que já errou — e gradua de estagiário a sênior. Aprendizado que se
repete em 2+ clientes (ou que o Marcos confirma como geral) **sobe pra Base Mãe** (`niches-library/design-principles/`).

## A foto vem DEPOIS do conteúdo
Nunca foto aleatória (foge do contexto = genérico). O cérebro define a copy e gera `foto_busca` (palavras que
descrevem a foto EXATA que aquele conteúdo pede) → só então busca ESSA foto. A foto serve à mensagem, não o contrário.
